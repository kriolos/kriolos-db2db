*db2db* is an industrial-grade, multi-dialect database migration framework re-engineering the capabilities of Perl-based *ora2pg* into modern, high-performance Java (targeting **JDK 25**, **Quarkus 4**, and **GraalVM Native Image**).

db2db supports extracting schema metadata, migrating schema DDL, converting procedural code (PL/SQL to PL/pgSQL), transforming spatial geometries (Oracle SDO_GEOMETRY to PostGIS), generating migration assessment reports, and streaming table data in parallel via PostgreSQL `COPY FROM STDIN` using JDK 25 Virtual Threads.

---

== 1. Architecture Overview

db2db is architected as a Maven multi-module system:

[source]
----
db2db/
├── pom.xml                 # Reactor POM (JDK 25, Quarkus 4 BOM, dependency management)
├── db2db-core/             # Engine, Extractors, DDL, Transpiler, Spatial, Assessment, Streaming
├── db2db-cli/              # Picocli-based standalone shaded CLI runner
└── db2db-web/              # Quarkus 4 REST, WebSocket, OpenAPI, Single-Page Web Dashboard & GraalVM Native Image
----

== 2. Supported Database Dialects & Sources

db2db implements the sealed `DialectDataTypeMapper` strategy and `MetadataExtractor` SPI across multiple DBMS sources:

* **Oracle Database** (11g, 12c, 19c, 21c, 23ai): System dictionary metadata (`ALL_TABLES`, `ALL_TAB_COLS`, `ALL_CONSTRAINTS`, `ALL_INDEXES`), partition schemas (RANGE, LIST, HASH), sequence parameters, and spatial `SDO_GEOMETRY`.
* **MySQL** (5.7, 8.x): `information_schema` extraction, enum/set mappings, autoincrement sequence emulation.
* **Microsoft SQL Server** (2016, 2019, 2022): `sys.tables`, `sys.columns`, identity columns, uniqueidentifiers, datetimeoffset.
* **Generic ANSI / JDBC**: Universal fallback extractor querying `java.sql.DatabaseMetaData`.

== 3. Modern Java 25 Language Features

db2db strictly enforces modern Java idioms throughout all modules:

* **Java Records**: Immutable carrier DTOs (`Table`, `Column`, `Constraint`, `Index`, `PartitionInfo`, `SdoGeometry`, `TranspileRequest`, `AssessmentReport`).
* **Pattern Matching for Switch & `instanceof`**: Type-safe extraction of metadata objects and AST dispatch without unchecked casts.
* **Switch Expressions**: Exhaustive `switch (...) ->` constructs with zero fall-through risk.
* **Text Blocks (`"""`)**: Clean, formatted SQL statements, DDL definitions, and HTML report templates.
* **Sequenced Collections**: Direct usage of `getFirst()`, `getLast()`, and `reversed()` on ordered collections.
* **Virtual Threads (`Thread.ofVirtual()`)**: Unbounded parallel table streaming and asynchronous assessment using `Executors.newVirtualThreadPerTaskExecutor()`.

== 4. Building the Project

=== Prerequisites

* **JDK 25** (e.g. Eclipse Temurin or GraalVM CE 25):
[source,bash]
----
sdk use java 25.0.4-tem
----
* **Apache Maven 3.9+**:
[source,bash]
----
mvn -version
----

=== Standard JVM Build

[source,bash]
----
mvn clean package
----

Artifacts produced:

* `db2db-core/target/db2db-core-1.0.0-SNAPSHOT.jar`
* `db2db-cli/target/db2db-cli-1.0.0-SNAPSHOT.jar` (Executable shaded JAR)
* `db2db-web/target/quarkus-app/` (Quarkus fast-jar runner)

=== GraalVM Native Image Compilation

Compile `db2db-web` into an ultra-fast, zero-JVM native executable:

[source,bash]
----
sdk use java 25.0.2-graalce
mvn clean package -Pnative -DskipTests
----

Result:
* Standalone native binary: `db2db-web/target/db2db-web-1.0.0-SNAPSHOT-runner`
* Startup time: **~35 milliseconds**
* Binary size: **~65 MB**

== 5. CLI Usage (`db2db-cli`)

The CLI offers commands mirroring `ora2pg` functionality:

[source,bash]
----
java -jar db2db-cli/target/db2db-cli-1.0.0-SNAPSHOT.jar --help
----

=== Subcommands

==== 1. Test Connection
[source,bash]
----
java -jar db2db-cli/target/db2db-cli-1.0.0-SNAPSHOT.jar test-connection \
  --url "jdbc:oracle:thin:@//localhost:1521/ORCLPDB1" \
  --user "HR" \
  --password "secret"
----

==== 2. Analyze & Estimate Migration Cost
[source,bash]
----
# Run live schema assessment against connected database:
java -jar db2db-cli/target/db2db-cli-1.0.0-SNAPSHOT.jar analyze \
  --config ora2pg.conf \
  --output ./assessment-report.html \
  --format HTML

# Or generate a complete Showcase/Fake Assessment Report (all features, no database required):
java -jar db2db-cli/target/db2db-cli-1.0.0-SNAPSHOT.jar --output ./reports analyze \
  --sample \
  --format html
----

==== 3. Export Schema DDL
[source,bash]
----
java -jar db2db-cli/target/db2db-cli-1.0.0-SNAPSHOT.jar export-schema \
  --dialect ORACLE \
  --schema HR \
  --output ./hr-schema.sql
----

==== 4. Stream Data in Parallel
[source,bash]
----
java -jar db2db-cli/target/db2db-cli-1.0.0-SNAPSHOT.jar export-data \
  --config ora2pg.conf \
  --target-url "jdbc:postgresql://localhost:5432/targetdb" \
  --target-user "postgres" \
  --target-password "secret" \
  --concurrency 16
----

==== 5. Transpile PL/SQL Code
[source,bash]
----
java -jar db2db-cli/target/db2db-cli-1.0.0-SNAPSHOT.jar convert-sql \
  --input ./oracle_package.sql \
  --output ./pg_package.sql
----

== 6. Web Dashboard & REST API (`db2db-web`)

Run the application either via JVM fast-jar or native runner:

[source,bash]
----
# Via JVM
java -jar db2db-web/target/quarkus-app/quarkus-run.jar

# Or via Native Binary (0.035s startup)
./db2db-web/target/db2db-web-1.0.0-SNAPSHOT-runner
----

Open your browser at `http://localhost:8080/`:

* **Web UI Dashboard**: `http://localhost:8080/index.html` (interactive PL/SQL transpiler, connection tester, assessment triggers).
* **Swagger UI / OpenAPI**: `http://localhost:8080/q/swagger-ui/`
* **Health Check**: `http://localhost:8080/api/v1/health`
* **Transpiler API**: `POST /api/v1/transpile`
* **Assessment API**: `POST /api/v1/assessment`
* **Showcase Report JSON**: `GET /api/v1/assessment/sample`
* **Showcase Report HTML**: `GET /api/v1/assessment/sample/html`
* **WebSocket Progress**: `ws://localhost:8080/ws/migration`
